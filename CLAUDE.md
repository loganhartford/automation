# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**Startup Scout** — an automated pipeline that monitors tech/startup newsletters for hardware companies worth joining as a senior embedded/firmware engineer. Newsletters are forwarded to a dedicated Gmail inbox, evaluated by Claude, and compiled into a weekly HTML report. The evaluation is written from the perspective of a senior firmware/embedded engineer considering companies to join, not an investor.

Target company profile: hardware startup, 30–100 people, pre-Series B, novel technology, strong timing.

## Setup

```bash
python3 -m venv venv
source venv/bin/activate
pip install anthropic python-dotenv google-auth google-auth-oauthlib google-api-python-client markdown
mkdir logs
```

**Required secrets (git-ignored):**
- `.env` — contains `ANTHROPIC_API_KEY`
- `credentials.json` — Google OAuth client secrets from the `startup-scout` Google Cloud project
- `token.pickle` — generated by running the OAuth flow locally on a Mac (browser required), then `scp`'d to the server; never committed to git

The OAuth flow must be run locally — do not attempt it on the server:
```bash
python3 ingest.py  # opens browser, writes token.pickle
```

After credential rotation, manually `scp` both `credentials.json` and `token.pickle` to the server.

## Running

```bash
# Process all unread scout emails
python3 ingest.py

# Generate and email this week's report now
python3 report.py

# Process a single newsletter file directly
python3 evaluate.py newsletters/strictlyvc1.txt

# Reset notified_date on companies (for re-testing reports)
python3 reset_reports.py
```

## Deployment

Runs on a DigitalOcean droplet (Ubuntu 24.04, 1GB RAM, SFO2, IP `167.172.204.113`) under the `scout` user.

**systemd user timers** (not cron):
- `scout-ingest.timer` — runs `ingest.py` hourly
- `scout-report.timer` — runs `report.py` daily at 7am

`loginctl enable-linger scout` must be set for timers to run when the scout user is not logged in.

Do not use VS Code Remote on this server — 1GB RAM is too small for it. Use plain SSH.

Logs go to `logs/ingest.log` and `logs/report.log`. Failures trigger an alert email to `logan.hartford@outlook.com`.

## Architecture

**Data flow:** Gmail inbox → `ingest.py` → `evaluate.py` → `scout.db` → `report.py` → email

### Module responsibilities

- **`ingest.py`** — Reads unread emails from `loganhartford.scout@gmail.com`, calls `evaluate.process_newsletter()` for each, marks them read.
- **`evaluate.py`** — LLM pipeline with three Claude calls per newsletter:
  1. `extract_companies()` — extracts startup names/descriptions as structured JSON
  2. `check_dealbreakers()` — evaluates 5 binary criteria; any `false` answer skips the company entirely
  3. `generate_report()` — 6-dimensional analysis for companies that pass all dealbreakers
- **`db.py`** — SQLite wrapper around `scout.db`. Deduplication is case-insensitive name matching only — no fuzzy matching ("Acme Inc" and "Acme Corp" are treated as different companies).
- **`gmail.py`** — Gmail API helpers: OAuth, reading unread emails, sending HTML emails.
- **`report.py`** — Queries unreported companies, renders styled HTML, emails report, sets `notified_date`.
- **`reset_reports.py`** — Dev utility to clear `notified_date` for re-testing.

### Database schema

Single table `companies` in `scout.db`:

| Column | Type | Notes |
|--------|------|-------|
| `name` | TEXT UNIQUE | Dedup key, case-insensitive |
| `first_seen` | TEXT | ISO timestamp |
| `source` | TEXT | Newsletter subject line |
| `passed_dealbreakers` | INTEGER | 1/0 |
| `report` | TEXT | JSON blob (see below) |
| `notified_date` | TEXT | NULL until included in a weekly report |

The `report` JSON blob stores everything that doesn't have its own column: `_description` (extracted from newsletter), `dealbreakers` (reasons for each criterion), and the 6-dimensional analysis. This keeps the schema flat at the cost of some awkward JSON handling in `report.py`.

### LLM patterns

- All Claude calls use **forced tool use** (`tool_choice={"type": "tool", "name": "..."}`) — this guarantees schema-conformant output and eliminates JSON parsing errors vs. asking the model to return raw JSON.
- Model: `claude-opus-4-6`
- `max_tokens` for the extraction call must be at least 4096 — lower values cause silent mid-response truncation.
- Retry logic: exponential backoff (10s → 20s → 40s → 80s) on `overloaded_error`, max 4 retries, via `call_with_retry()`.
- A failed evaluation for one company does not abort the rest of the newsletter batch.

### HTML report generation

- Report is sent as HTML email with a plain-text fallback — not markdown.
- The `markdown` library's `Markdown` class must be instantiated before calling `.convert()` — `md.convert()` called directly on the class does not work.
