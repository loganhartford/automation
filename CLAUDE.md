# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**Startup Scout** — an automated pipeline that monitors tech/startup newsletters for hardware companies worth joining as a senior embedded/firmware engineer. Newsletters are forwarded to a dedicated Gmail inbox, evaluated by Claude, and compiled into a weekly HTML report. The evaluation is written from the perspective of a senior firmware/embedded engineer considering companies to join, not an investor.

Target company profile: hardware startup, 30–100 people, pre-Series B, novel technology, strong timing.

## Setup

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
mkdir -p logs
```

**Required secrets (git-ignored):**
- `.env` — contains `ANTHROPIC_API_KEY`, `TELEGRAM_SCOUT_BOT_TOKEN`, `TELEGRAM_SCOUT_CHAT_ID`
- `credentials.json` — Google OAuth client secrets from the `startup-scout` Google Cloud project
- `token.pickle` — generated by running the OAuth flow locally (browser required); never committed to git
- `calendar_token.pickle` — Google Calendar OAuth token; separate from Gmail, same `credentials.json`

The OAuth flow requires a browser — run it locally if on a headless machine:
```bash
python3 ingest.py  # opens browser, writes token.pickle
```

## Running

```bash
# Process all unread scout emails
python3 ingest.py

# Generate and email this week's report now
python3 report.py

# Process a single newsletter file directly
python3 evaluate.py newsletters/strictlyvc1.txt

# Run the Telegram bot (long-polling, stays running)
python3 scout_bot.py

# Reset notified_date on companies (for re-testing reports)
python3 reset_reports.py
```

## Deployment

Runs on a local always-on Linux desktop (Ubuntu 24.04) under the `logan` user at `/home/logan/automation`.

**systemd user timers** (not cron):
- `scout-ingest.timer` — runs `ingest.py` hourly
- `scout-report.timer` — runs `report.py` daily at 7am

**systemd user services:**
- `scout-bot.service` — runs `scout_bot.py` (long-polling Telegram bot, always-on)
- `scout-schedule.service` — runs the Flask scheduler via gunicorn on port 5001

Unit files live at `~/.config/systemd/user/`. Linger is enabled (`loginctl enable-linger logan`) so services run without an active login session.

Logs go to `logs/ingest.log`, `logs/report.log`, `logs/bot.log`, and `logs/schedule.log`.

**Firewall:** UFW is active, only port 22 (SSH) is open. Ports 80/443 are not forwarded — all inbound web traffic arrives via Cloudflare Tunnel.

## Architecture

**Data flow:** Gmail inbox → `ingest.py` → `evaluate.py` → `scout.db` → `report.py` → email

### Module responsibilities

- **`ingest.py`** — Reads unread emails from `loganhartford.scout@gmail.com`, calls `evaluate.process_newsletter()` for each, marks them read.
- **`evaluate.py`** — LLM pipeline with three Claude calls per newsletter:
  1. `extract_companies()` — extracts startup names/descriptions as structured JSON
  2. `check_dealbreakers()` — evaluates 5 binary criteria; any `false` answer skips the company entirely
  3. `generate_report()` — 6-dimensional analysis for companies that pass all dealbreakers
- **`db.py`** — SQLite wrapper around `scout.db`. Deduplication is case-insensitive name matching only — no fuzzy matching ("Acme Inc" and "Acme Corp" are treated as different companies).
- **`gmail.py`** — Gmail API helpers: OAuth, reading unread emails, sending HTML emails.
- **`report.py`** — Queries unreported companies, renders styled HTML, emails report, sets `notified_date`.
- **`scout_bot.py`** — Telegram bot (long-polling). User sends a company name; bot looks up a description via Claude, runs dealbreakers and (if passing) generates a full report, sends the report back via Telegram and emails it via `send_single_company_report`. Companies evaluated this way are saved to `scout.db` and marked notified so they won't appear in the weekly report. Runs as a systemd user service `scout-bot`.
- **`reset_reports.py`** — Dev utility to clear `notified_date` for re-testing.

### Database schema

Single table `companies` in `scout.db`:

| Column | Type | Notes |
|--------|------|-------|
| `name` | TEXT UNIQUE | Dedup key, case-insensitive |
| `first_seen` | TEXT | ISO timestamp |
| `source` | TEXT | Newsletter subject line |
| `passed_dealbreakers` | INTEGER | 1/0 |
| `report` | TEXT | JSON blob (see below) |
| `notified_date` | TEXT | NULL until included in a weekly report |

The `report` JSON blob stores everything that doesn't have its own column: `_description` (extracted from newsletter), `dealbreakers` (reasons for each criterion), and the 6-dimensional analysis. This keeps the schema flat at the cost of some awkward JSON handling in `report.py`.

### LLM patterns

- All Claude calls use **forced tool use** (`tool_choice={"type": "tool", "name": "..."}`) — this guarantees schema-conformant output and eliminates JSON parsing errors vs. asking the model to return raw JSON.
- Model: `claude-opus-4-6`
- `max_tokens` for the extraction call must be at least 4096 — lower values cause silent mid-response truncation.
- Retry logic: exponential backoff (10s → 20s → 40s → 80s) on `overloaded_error`, max 4 retries, via `call_with_retry()`.
- A failed evaluation for one company does not abort the rest of the newsletter batch.

### HTML report generation

- Report is sent as HTML email with a plain-text fallback — not markdown.
- The `markdown` library's `Markdown` class must be instantiated before calling `.convert()` — `md.convert()` called directly on the class does not work.

## Scheduler

Telegram-based scheduling assistant. No public web surface — all booking management happens via Telegram. External attendees book using Google Calendar's native appointment scheduling feature. Runs as systemd user service `scout-schedule`.

### Running

```bash
# Start/restart the Telegram bot
systemctl --user restart scout-schedule

# Check calendar notification timer
systemctl --user status scout-calendar-notify.timer
```

### Module responsibilities

- **`telegram_bot.py`** — Standalone long-polling Claude agent (`claude-opus-4-6`) with 4 tools: `list_bookings`, `reschedule_booking`, `cancel_booking`, `email_participant`. In-memory conversation history (last 20 messages per chat, resets on service restart). Only responds to `TELEGRAM_SCHEDULER_CHAT_ID`. Run directly as `python3 telegram_bot.py`.
- **`calendar_api.py`** — Google Calendar helpers using a separate `calendar_token.pickle` OAuth token (scope: `calendar`). Key functions: `get_upcoming_bookings()`, `reschedule_booking()`, `cancel_booking()`.
- **`calendar_notify.py`** — Oneshot script run every 5 min by `scout-calendar-notify.timer`. Polls Google Calendar for new events with external attendees; sends Telegram notification via `telegram_notifier`. State tracked in `logs/calendar_notify_state.json`.
- **`telegram_notifier.py`** — One-way Telegram notification helper used by `calendar_notify.py`.

### Calendar event details

- `sendUpdates="all"` on insert/update/delete so Google Calendar handles invite/reschedule/cancellation emails automatically

### Required secrets

```

TELEGRAM_SCHEDULER_CHAT_ID
```

`calendar_token.pickle` — OAuth token for Google Calendar. Must be generated locally (browser required). Uses same `credentials.json` as Gmail but separate token file and scope.
